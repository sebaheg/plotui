title: 3D plots
description: Scatter clouds, pickable graphs, trajectories, Gouraud-shaded surfaces, and triangle meshes under one orbit camera.
---

Any 3D trace switches the whole plot to the orbit camera: drag rotates as a
trackball — the drag grabs the object, so dragging right turns it right —
shift-drag pans, scroll zooms, double-click resets. Prefer the opposite,
camera-grab feel? Every frontend's `set_input_map` accepts a `-` prefix to
invert an axis: `set_input_map("-yaw", "-pitch")`.

For a view that turns on its own, call `spin(step)` rather than
`rotate(step, 0)`. It owns the direction — a positive step turns the object
the way a rightward drag pushes it, and `set_input_map("-yaw")` inverts the
two together. A spin that runs *against* the drag is the one camera bug you
cannot see coming: on a point cloud or a wireframe nobody can tell which way
the scene is turning, so it goes unnoticed until something opaque is on
screen, and then it reads as the drag being inverted — you push the object
right, let go, and it walks back the way it came.

All 3D traces share one
(x, y, z) space — no axis is special — with a bounding-box wireframe for
orientation (`set_show_box(False)` hides it) and depth fog for distance
cueing. Named 3D traces get the same legend as 2D charts, and colors follow
the same rules — omitted colors take colorway slots, and shorthand strings
work everywhere (see [Colors](/docs/charts-2d#colors)).

## Scatter

```python
plot.add_scatter3d(xs, ys, zs, color=None, size=3.0, name="Cluster A")
```

`add_scatter3d` returns a trace handle, and `extend` appends points through
it in place — bounds and pick indices update incrementally, so a point cloud
can stream in live while the camera keeps moving:

```python
h = plot.add_scatter3d([], [], [])   # start empty
plot.extend(h, xs, ys, zs)           # each batch as it arrives — no rebuilds
```

`plotui example lidar` is a complete version of this recipe: a simulated
LiDAR sweep scanning a room, streamed beam by beam
(`--out lidar.mp4` records it to a video).

## Graphs

Node-link graphs with per-node styling and interactive picking:

```python
plot.add_graph3d(
    xs, ys, zs,
    edges=[(0, 1), (1, 2)],
    node_colors=[...],          # per node, else uniform `color`
    node_sizes=[...],           # per node, else `size`
    edge_colors=[...],          # per edge, else dimmed endpoint blend
    node_shapes=["disc", "ring", "square", "triangle", "diamond",
                 "diamond-open", "dot"],
    name="mesh",                # optional: puts the graph in the legend
)
```

Hovered nodes and edges light up white; clicks select. See
[Interaction](/docs/interaction).

### Live graphs

Graphs are mutable in place, without rebuilds:

```python
plot.set_graph_positions(h, xs, ys, zs)   # move every node (per-frame call)
plot.set_graph_colors(h, node_colors, edge_colors)  # recolor; edge_colors=None
                                          # restores the default edge blend
plot.extend_graph(h, xs, ys, zs,          # append nodes + edges — new nodes
    node_colors=[...], edges=[(0, 9)])    # arrive without a rebuild
```

Structure is untouched by `set_graph_positions`/`set_graph_colors`, so node
and edge indices — and with them hover and selection — stay valid across
every frame. The recolor call is the highlight primitive: on hover, dim
everything and brighten the hovered node's dependency closure, then restore.

### Force-directed layout

`ForceLayout` is the motion half: connected nodes attract like springs, all
nodes repel, and a cooling temperature settles the layout. It's pure math —
the host owns the timer:

```python
from plotui import ForceLayout, Plot

lay = ForceLayout(n, edges, seed=7)       # deterministic per seed
h = plot.add_graph3d(*lay.positions(), edges=edges)

def tick():                               # ~30 Hz host timer
    if lay.step() >= 1e-3:                # returns mean displacement;
        plot.set_graph_positions(h, *lay.positions())  # below 1e-3 = settled

idx = lay.add_node([2, 3])                # a new node flies in beside its
plot.extend_graph(h, ...,                 # first neighbor, and the sim
    edges=[(2, idx), (3, idx)])           # re-heats locally
```

Pin `plot.set_bounds(lo, hi)` once the rough extent is known so the frame
doesn't re-center while the simulation runs. `plotui example deps` and
`examples/textual_deps.py` are complete versions of this recipe.

## Lines

Polylines — trajectories, orbits, curves — in the same space as scatter:

```python
plot.add_line3d(xs, ys, zs, color=None, width=2.0, name=None)
```

Strokes carry interpolated depth, so lines occlude correctly against other
geometry. A NaN vertex breaks the line into separate runs. Vertices are not
pickable, so adding lines never shifts existing node indices.

## Surfaces

Grid surfaces, Gouraud-shaded with a headlight and a height colormap:

```python
plot.add_surface3d(
    xs, ys, Z,               # Z[j][i] is the height at (xs[i], ys[j])
    colormap="viridis",      # or "plasma"; None + `color` for a solid surface
    wireframe=False,         # overlay the grid lines
    name=None,
)
```

`Z` is a list of rows or a 2D NumPy array. Every vertex gets its own ramp
color, normal, and fog depth, interpolated across each cell — surfaces render
as smooth gradients, not flat facets. Cells with a NaN corner become holes.
Grid vertices are not pickable.

The z-buffer handles occlusion globally: a trajectory drawn through a surface
disappears behind hills and re-emerges, with no ordering to manage.

## Meshes

Arbitrary geometry — iso-surfaces, scanned models, anything that reduces to
triangles — shaded like a surface but free of the grid:

```python
plot.add_mesh3d(
    xs, ys, zs,              # the vertices
    tris,                    # [(a, b, c), ...] indices into them
    colormap="plasma",       # or None + `color` for a solid mesh
    name=None,
)
```

Triangles index the vertex arrays, so vertices shared between faces are
stored once and shaded once. Each vertex takes its normal from the facets
that meet there, which is what makes a mesh of shared vertices read as a
smooth surface rather than a field of facets; shading is two-sided, so
either winding draws and there is no backface to cull. The colormap runs
over the mesh's own z range. A triangle with a NaN vertex is skipped, the way
a surface cell with a NaN corner is a hole; an index naming no vertex is
rejected outright, because a silently dropped face is a data bug worth
hearing about. Mesh vertices are not pickable, so adding a mesh never shifts
existing node indices.

`marching_cubes(values, nx, ny, nz, origin, cell, iso)` turns a sampled
scalar field into exactly these two arrays, sharing vertices along cell
edges so the result shades smoothly across cells.

`catmull_rom`, `tube` and `ribbon` cover the other way meshes get made:
sweeping a cross-section along a path. `catmull_rom(path, per_segment)`
resamples a coarse polyline into a smooth one — control points a spline
passes through, not near. `tube(path, radii, sides)` and `ribbon(path, up,
widths, thickness)` then sweep a circle or a flat rectangle along it, both
carrying a rotation-minimizing frame so the section does not spin about its
own axis wherever the path twists. Radii and widths are per point, so a
tube tapers and a ribbon can end in an arrowhead; `ribbon` also takes a
per-point face normal, for callers with a real orientation to impose rather
than an arbitrary one. All three are available in Rust and JavaScript,
alongside `marching_cubes`.

Meshes are available in Rust and JavaScript today; the Python binding above
is the shape it will take. Run `plotui example mandelbulb` to see one — the
Mandelbulb fractal, polygonised and revealed slice by slice — or `plotui
example protein`, which sweeps ubiquitin's backbone into a cartoon: helices
and strands as ribbons turned by the peptide plane, loops as tubes, folding
in from the N terminus. That example is worth reading as well as running.
Everything about proteins in it — PDB column offsets, which fold a residue
belongs to, the flip and smoothing that keep a pleated beta strand from
corkscrewing — lives in the example, not in plotui. The library draws
geometry; the domain stays in the caller.
